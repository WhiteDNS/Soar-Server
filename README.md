# WhiteDNS Soar Panel

[English installation guide](docs/PANEL.en.md) · [راهنمای فارسی](docs/PANEL.fa.md)

[دامنه‌های جایگزین تونل و پنل](docs/DOMAINS.fa.md): حداکثر ۸ دامنه برای هر بخش، بدون ساخت دوبارهٔ حساب‌ها یا تغییر سهمیه. نصب اولیه همچنان فقط یک دامنه می‌خواهد.

پنل مدیریت سرور **WhiteDNS 0.7.0** با موتورهای **Soar و Cotten** برای **Ubuntu 22.04/24.04/26.04 یا Debian 12/13، معماری amd64/x86_64 یا arm64/aarch64**.

**CottenDNS** نیز از [فورک سازگار WhiteDNS](https://github.com/WhiteDNS/CottenDns) و با حفظ نام و مجوز نویسندگان اصلی اضافه شده است.

موتور اصلی **Soar توسط [Lantern / GetLantern](https://github.com/getlantern/soar) توسعه یافته است**. WhiteDNS پنل، نصب‌کننده و یکپارچه‌سازی کلاینت را توسعه می‌دهد.

## نصب پنل با یک دستور

برای نصب معمول، دستور زیر کافی است. اگر فایل نصب را از قبل دانلود کرده‌اید، [نصب از فایل بسته](docs/LOCAL-COTTEN.fa.md) را ببینید.

با SSH وارد سرور شوید و اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/WhiteDNS/Soar-Server/main/panel-setup.sh)
```

نصب‌کننده نسخهٔ پایدار مشخص‌شده و checksum آن را از Releases دریافت و بررسی می‌کند؛ سپس هفت مرحلهٔ نصب را با توضیح هر مرحله پیش می‌برد. دسترسی root یا sudo و systemd لازم است؛ Go، Docker، Node یا پایگاه دادهٔ جدا روی سرور لازم نیست. متن ترمینال **انگلیسی و ASCII** است تا در SSH درست نمایش داده شود.

در ۰.۳.۱، رکوردهای A/NS پیش از تغییر سرویس بررسی می‌شوند؛ SOA و اتصال واقعی HTTPS از داخل تونل پس از شروع سرویس آزموده می‌شوند. خطای DNS جزئیات و امکان تلاش دوباره دارد. حساب آزمایش موقت و محدود است و در پایان حذف می‌شود. اگر آزمون اتصال نگذرد، می‌توانید مشکل را رفع و دوباره تست کنید، به وضعیت قبلی برگردید یا صریحاً نصب «تأییدنشده» را نگه دارید؛ در حالت آخر دستور با وضعیت غیرصفر پایان می‌یابد.

اگر UFW فعال باشد، نصب‌کننده پس از تأیید نصب UDP/53 و TCP/53 و در حالت مستقیم پورت مدیریت TCP را باز می‌کند. فایروال ارائه‌دهنده و NAT همچنان باید در پنل ارائه‌دهنده تنظیم شوند. سرویس نگهداری نیز هنگام شروع، بازبودن UDP/TCP 53 در UFW فعال را بررسی می‌کند. برای اجرای مجدد بررسی DNS و آزمون‌های کامل نصب روی سرور موجود، نصب‌کننده را دوباره اجرا کنید؛ به‌روزرسانی باینری به‌تنهایی این آزمون‌ها را اجرا نمی‌کند.

اگر `curl` نصب نیست، ابتدا اجرا کنید:

```bash
sudo apt-get update
sudo apt-get install -y curl
```

**[راهنمای قدم‌به‌قدم فارسی: DNS، نصب، ورود، ساخت حساب و اتصال گوشی](docs/PANEL.fa.md)**

به دامنه و دسترسی پنل DNS آن نیاز دارید. رکورد A برای nameserver و رکورد NS برای زیردامنهٔ جدا بسازید؛ نمونهٔ دقیق در راهنماست. پورت UDP/53 و TCP/53 باید در دسترس باشد. رکوردهای MasterDNS یا CottenDNS فعال را تغییر ندهید. نصب‌کننده پیش از جایگزینی سرور مستقل قبلی، تأیید صریح مهاجرت می‌گیرد.

## بعد از نصب

آدرس کامل پنل در پایان نصب نمایش داده می‌شود؛ **مسیر تصادفی انتهای آدرس را ذخیره کنید**. بازکردن IP یا دامنه بدون آن مسیر، صفحهٔ ورود را نشان نمی‌دهد.

1. با حساب مدیر وارد شوید و در «دامنه و امنیت»، دامنه و HTTPS را تنظیم کنید. این کار با `sudo soar-panel-security` در ترمینال هم قابل انجام است.
2. در «حساب‌های کاربری»، حساب بسازید و حجم، تاریخ انقضا، سرعت و سقف جریان هم‌زمان را تعیین کنید.
3. از «لینک / QR»، «لینک ساب» را انتخاب و آدرس یا QR آن را در بخش Import اپ [WhiteDNS](https://github.com/WhiteDNS/WhiteDNS-Android/releases) وارد کنید. لینک مستقیم هم همچنان در دسترس است.

برای ساب کامل از **[WhiteDNS 1.6.8 یا جدیدتر](https://github.com/WhiteDNS/WhiteDNS-Android/releases/latest)** استفاده کنید. پس از تغییر تنظیمات تونل، ساب را در اپ تازه‌سازی کنید؛ برای لینک مستقیم، پروفایل را دوباره Import کنید. [راهنمای ساب، حجم، انقضا و تعویض لینک](docs/SUBSCRIPTIONS.md) · [گزارش آزمون پنل و اپ](docs/SUBSCRIPTIONS-VERIFICATION-2026-10-18.md).

در فرم حساب، «Soar و Cotten (پیشنهادی)» هر دو روش اتصال را در یک ساب می‌دهد. دامنه و کلید دیگری لازم نیست؛ حجم، انقضا و سرعت مشترک‌اند. حساب‌های قبلی و لینک Soar آن‌ها حفظ می‌شوند.

نسخهٔ کد منبع 0.7.0 است؛ نصب‌کنندهٔ عمومی تا انتشار و تأیید فایل‌های 0.7.0 روی نسخهٔ پایدار منتشرشدهٔ 0.6.0 می‌ماند.

[مدیریت با تلگرام / Telegram management](docs/TELEGRAM.md): اتصال با توکن ربات و لینک یک‌بارمصرف، مدیریت حساب‌ها، راه‌اندازی مجدد و ارتقای پنل، هشدار و گزارش روزانه.

## امکانات و ارتقا

- تغییر نام کاربری و رمز ورود از «حساب مدیر»، با تأیید رمز فعلی و خروج همهٔ نشست‌های قبلی.
- انتخاب چند حساب یا همهٔ نتایج جست‌وجو و حذف گروهی با تأیید نهایی.

- داشبورد واقعی منابع سرور، مصرف و جریان‌ها؛ رابط فارسی/انگلیسی با چیدمان مناسب هر زبان، روشن/تیره و سازگار با موبایل.
- حساب مستقل با لینک و QR، حجم مشترک آپلود/دانلود، انقضا، سرعت و سقف جریان TCP؛ قطع اتصال، تعویض کلید و خروجی CSV.
- ساب مستقل هر حساب با لینک و QR، حجم و انقضا، تازه‌سازی تنظیمات و تعویض آدرس بدون تغییر کلید تونل.
- تنظیمات پیشرفته با توضیح روی علامت سؤال؛ حالت خودکار، مسیر محدود، متعادل و کارایی بیشتر.
- پشتیبان، بازیابی و به‌روزرسانی از خود پنل با تأیید رمز مدیر و بازگشت در صورت شکست فعال‌سازی.
- دامنه، HTTPS با تمدید خودکار گواهی و مسیر ورود تصادفی؛ تنظیم از پنل یا ترمینال.

نسخهٔ پایدار فقط به‌روزرسانی‌های پایدار را پیشنهاد می‌دهد. کاربران beta8 و جدیدتر می‌توانند از خود پنل به 0.6.0 ارتقا دهند؛ نسخه‌های قدیمی‌تر باید یک‌بار نصب‌کنندهٔ بالا را اجرا کنند تا سرویس نگهداری نصب شود. حساب‌ها، کلیدها، مصرف، تنظیمات ذخیره‌شده و مسیر ورود موجود حفظ می‌شوند. پیش از ارتقا پشتیبان بگیرید.

## محدوده و بررسی

این انتشار پایدارِ **پنل مدیریت** است. پورت‌های مقصد پیش‌فرض 80/443 هستند؛ UDP/QUIC و همهٔ بازی‌ها یا تماس‌ها پوشش داده نمی‌شوند. شمارش جریان TCP معادل شمارش دستگاه نیست و لینک مشترک، هویت مشترک حساب دارد.

آزمون‌های Go، race، نصب‌کننده، بازیابی/ارتقا و رابط مرورگر در [GitHub Actions](https://github.com/WhiteDNS/Soar-Server/actions/workflows/panel.yml) اجرا می‌شوند. آزمون گوشی فیزیکی، شبکه‌های ایران و بار تولیدی گسترده هنوز کامل نیست. [گزارش اختلال مرورگر](docs/SOAR-WEB-RELIABILITY-2026-10-18.fa.md) نتایج و توقف مقطعی مشاهده‌شده را ثبت کرده است؛ پاسخ بررسی ربات آمازون معادل بازشدن کامل فروشگاه نیست.

## نصب قدیمی بدون پنل

راهنمای [SERVER-GUIDE.fa.md](SERVER-GUIDE.fa.md) و دستور زیر برای سرور مستقل قدیمی باقی می‌مانند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/WhiteDNS/Soar-Server/main/setup.sh)
```

این دستور **پنل نصب نمی‌کند**؛ مدیریت آن با `sudo soar-manager` است. مهاجرت از پروفایل مشترک سرور مستقل به حساب‌های پنل، به تأیید مهاجرت و لینک‌های تازهٔ حساب‌ها نیاز دارد.

## ساخت از سورس

Go 1.26.1، Python 3 و Bash در محیط توسعه لازم‌اند:

```bash
python3 scripts/prepare_cotten_engine.py --workspace .engine-source/patched.go.work
export GOWORK="$PWD/.engine-source/patched.go.work"
go build -o .engine-source/cotten-client ./.engine-source/CottenDNS/cmd/client
bash tests/panel_installer_test.sh
bash tests/panel_bootstrap_test.sh
PANEL_COTTEN_CLIENT="$PWD/.engine-source/cotten-client" go test ./... -count=1 -timeout 240s
go test -race ./internal/panel ./internal/panelops -count=1 -timeout 300s
go vet ./...
python3 scripts/build_panel_bundle.py --arch amd64
python3 scripts/build_panel_bundle.py --arch arm64
bash dist/soar-panel-0.7.0-linux-amd64/panel-install.sh --check-bundle
```

نسخهٔ پایه، پچ و هش تمام فایل‌های موتور Cotten در `patches/cotten-engine.json`
ثبت شده‌اند. ابزار آماده‌سازی، پچ را روی همان commit اعمال و نتیجه را بررسی می‌کند؛
ساخت بسته نیز سورس متفاوت یا فایل کد اضافه را رد می‌کند. این مرحله تنظیمات،
کاربران یا پایگاه دادهٔ سرویس در حال اجرا را تغییر نمی‌دهد.
