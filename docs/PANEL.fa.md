# پنل مدیریت WhiteDNS Soar — نسخهٔ آزمایشی

این پنل **فقط روی سرور** نصب می‌شود. موتور تونل [Soar متعلق به Lantern](https://github.com/getlantern/soar) است؛ پنل و نصب‌کننده را WhiteDNS توسعه می‌دهد. چیدمان و گردش کار از [پنل سنایی / 3x-ui](https://github.com/MHSanaei/3x-ui) الهام گرفته، اما کد و دارایی‌های آن کپی نشده‌اند.

## امکانات این نسخه

- داشبورد CPU، حافظه، دیسک، مصرف کاربران و جریان‌های باز، با به‌روزرسانی هر هشت ثانیه.
- ساخت، ویرایش، جست‌وجو، فعال/غیرفعال‌سازی و حذف حساب؛ خروجی CSV.
- سقف حجم مشترک آپلود و دانلود، انقضای زمانی، سقف سرعت مشترک و محدودیت جریان TCP هم‌زمان.
- قطع اتصال‌های باز، صفر کردن مصرف و تعویض لینک و کلید با ابطال لینک قبلی.
- لینک استاندارد `soar://` و QR، سازگار با WhiteDNS 1.6.6؛ بدون تغییر اپ.
- تنظیم Resolverهای شروع، کشف مسیر ایران/جهانی و پورت‌های مقصد مجاز.
- ثبت رویدادهای مدیریت، پشتیبان کامل، بازیابی آفلاین و بازیابی رمز مدیر.
- ظاهر فارسی راست‌به‌چپ، تم روشن/تیره و نمایش موبایل.

این نسخه هنوز جایگزین تمام امکانات 3x-ui نیست: چندمدیری، فروش و پرداخت، چندسرور، اشتراک خودکار، تاریخچهٔ نموداری بلندمدت و شمارش دستگاه ندارد. استفاده در شبکهٔ واقعی ایران هنوز آزمایش نشده است.

## ۱. پیش‌نیاز

یک سرور Ubuntu 22.04/24.04/26.04 یا Debian 12/13 با معماری amd64، دسترسی root یا sudo و دامنه‌ای که پنل DNS آن در اختیار شماست. سرویس systemd باید فعال باشد. برای تداخل نداشتن با سرویس‌های دیگر، ابتدا روی سرور تست نصب کنید. برنامهٔ Windows، فقط برای توسعه است؛ سرور نهایی Linux است.

## ۲. رکوردهای DNS

فرض کنید دامنهٔ شما `example.com` و IP عمومی سرور `203.0.113.10` است. این IP فقط مثال است؛ IP خودتان را وارد کنید:

| نوع | نام در پنل DNS | مقدار | توضیح |
| --- | --- | --- | --- |
| A | `ns-soar` | IP عمومی سرور | حالت DNS-only، پراکسی خاموش |
| NS | `soar` | `ns-soar.example.com` | واگذاری `soar.example.com` |

پورت **UDP/53** باید از اینترنت به سرور برسد. TCP/53 بین کلاینت و Resolver ممکن است استفاده شود؛ موتور مرجع Soar در سرور روی UDP گوش می‌کند. این پنل DNS عمومی بازگشتی نیست.

رکوردهای MasterDNS یا Cotton را حذف یا جایگزین نکنید؛ مثلاً `t.example.com` را نگه دارید و برای Soar از `soar.example.com` استفاده کنید. روی یک نام، NSهای دو سرویس متفاوت قرار ندهید. برای هر حساب پنل، رکورد جدید لازم نیست؛ زیرنام‌های حساب زیر همان واگذاری پاسخ داده می‌شوند. دامنهٔ پایه حداکثر ۲۴ نویسه است تا نام حساب با محدودیت ۴۵ نویسهٔ کلاینت فعلی سازگار بماند.

## ۳. نصب بستهٔ آزمایشی

بستهٔ پنل از انتشار آزمایشی `panel-v0.2.0-beta7` همین مخزن دریافت می‌شود؛ نصب‌کنندهٔ پایدار `setup.sh` همچنان مخصوص سرور بدون پنل است. برای دریافت و اجرای نصب‌کنندهٔ پنل، در SSH سرور:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/WhiteDNS/Soar-Server/panel-v0.2.0-beta7/panel-setup.sh)
```

این دستور فایل نسخه‌دار و checksum را بررسی می‌کند و ترمینال را برای مراحل پرسش‌وپاسخ باز نگه می‌دارد. اگر `curl` یا `dig` نصب نیست، با `sudo apt-get update` و `sudo apt-get install -y curl dnsutils iproute2` آن‌ها را نصب کنید. برای دریافت دستی و نصب آفلاین، مراحل زیر نیز قابل استفاده است.

فایل `soar-panel-0.2.0-beta7-linux-amd64.tar.gz` و فایل کنار آن با پسوند `.sha256` را در یک پوشهٔ سرور قرار دهید، سپس:

```bash
sha256sum -c soar-panel-0.2.0-beta7-linux-amd64.tar.gz.sha256
tar -xzf soar-panel-0.2.0-beta7-linux-amd64.tar.gz
cd soar-panel-0.2.0-beta7-linux-amd64
sudo bash panel-install.sh
```

دستور اول باید `OK` نشان بدهد؛ اگر خطا دیدید نصب نکنید و فایل‌ها را دوباره دریافت کنید. نصب‌کننده هفت مرحله دارد: بررسی سرور، DNS، مدیر، روش ورود امن، مرور تغییرات، نصب و راهنمای اولین اتصال. خروجی SSH عمداً انگلیسی و ASCII است.

نصب‌کننده از شما دامنهٔ واگذارشده، IP محلی سرور، آدرس SSH و نام/رمز مدیر می‌پرسد. رمز روی صفحه نشان داده نمی‌شود. روی سرور NAT، IP محلی برای گوش‌دادن و IP عمومی برای رکورد A استفاده می‌شود. اسکریپت تنظیمات فایروال و وب‌سرور موجود را تغییر نمی‌دهد؛ UDP/53 را در فایروال میزبان و پنل ارائه‌دهنده اجازه دهید.

### مهاجرت از Soar بدون پنل

اگر `soar-server.service` فعال باشد، فقط پس از تایپ دقیق `MIGRATE` متوقف می‌شود. فایل و کلید قدیمی نگه داشته می‌شوند، اما **لینک‌های قبلیِ دامنهٔ مشترک در پنل کار نمی‌کنند**. باید حساب بسازید و لینک‌های جدید بدهید. این تغییر را در زمان مناسب انجام دهید. خرابی در فعال‌سازی، سرویس قبلی را دوباره راه می‌اندازد؛ مسیر پشتیبان خصوصی نیز نمایش داده می‌شود.

برای برگشت به سرویس قبلی:

```bash
sudo systemctl disable --now soar-panel
sudo systemctl enable --now soar-server
```

اجرای دوبارهٔ نصب‌کننده، حساب‌ها، مصرف، کلیدها و رمز مدیر را نگه می‌دارد. دامنهٔ پایگاه داده قابل تغییر خودکار نیست.

## ۴. باز کردن پنل

در مرحلهٔ چهارم نصب، روش ورود را انتخاب می‌کنید:

- **گزینهٔ ۱: مستقیم با IP و پورت.** در مرورگر آدرسی مثل `http://YOUR_SERVER_IP:2053` را باز کنید؛ تونل SSH لازم نیست. این گزینه برای سرور آزمایشی است و HTTP رمزگذاری ندارد. پورت را در همان مرحله می‌توانید تغییر دهید. نصب‌کننده اگر UFW فعال باشد یک قانون اجازه برای پورت مدیریتی انتخاب‌شده اضافه می‌کند؛ پورت TCP را در فایروال پنل ارائه‌دهنده و NAT نیز باز کنید.
- **گزینهٔ ۲: خصوصی با SSH یا پروکسی HTTPS.** پنل فقط روی loopback گوش می‌دهد. برای این حالت، روی کامپیوتر خود یک ترمینال جدا باز کنید و آدرس SSH سرور را جایگزین کنید:

```bash
ssh -N -L 2053:127.0.0.1:2053 root@YOUR_SERVER_IP
```

این ترمینال را باز نگه دارید. در مرورگر همان کامپیوتر [آدرس پنل محلی](http://127.0.0.1:2053) را باز کنید و با رمز مرحلهٔ نصب وارد شوید. اگر پورت محلی اشغال است، عدد سمت چپ را مثلاً `3053` کنید و در مرورگر نیز پورت 3053 را باز کنید. اگر SSH شما پورت دیگری دارد، گزینهٔ `-p` را اضافه کنید.

### ورود با دامنه و HTTPS

برای دسترسی مستقیم با موبایل، یک نام مجزا مثل `panel.example.com` با رکورد A رو به سرور بسازید و از reverse proxy دارای گواهی معتبر استفاده کنید. نمونهٔ بخش Caddyfile، پس از نصب Caddy و با حفظ سایر سایت‌های موجود:

```caddyfile
panel.example.com {
    reverse_proxy 127.0.0.1:2053
}
```

وب‌پروکسی باید روی همان سرور باشد، پورت‌های TCP/80 و TCP/443 برای وب در دسترس باشند، و نام نمونه با نام خودتان جایگزین شود. گزینهٔ `--trust-loopback-proxy` در حالت خصوصی، هدر HTTPS را فقط از loopback می‌پذیرد. Caddy را به‌عنوان مسیر ورود HTTPS خود پنل تنظیم کنید، نه پراکسی مسیر DNS تونل. برای HTTPS از گزینهٔ ۲ نصب استفاده کنید. اجرای مستقیم برنامه برای HTTP عمومی نیاز به انتخاب صریح `--allow-insecure-http` دارد؛ نصب‌کننده این گزینه را فقط در حالت دسترسی مستقیم قرار می‌دهد.

نصب تازه گزینهٔ ورود مستقیم را پیشنهاد می‌دهد. در نصب مجدد، حالت ورود قبلی به‌عنوان پیشنهاد حفظ می‌شود؛ پیش از تأیید، آدرس نهایی را در مرحلهٔ مرور تنظیمات بررسی کنید. ارتقای پنل از beta1، حساب‌ها، لینک‌ها، رمز و مصرف موجود را نگه می‌دارد.

## ۵. ساخت حساب و اتصال

از «حساب‌های کاربری» روی «حساب جدید» بزنید. نام، حجم کل بر حسب GiB، تاریخ و ساعت انقضا، سرعت بر حسب KiB/s و سقف جریان TCP را تنظیم کنید. حجم و سرعت صفر یعنی نامحدود؛ تاریخ خالی یعنی بدون انقضا. ساعت فرم به وقت دستگاه مدیر است و سرور زمان مطلق را ذخیره می‌کند؛ ساعت سرور باید درست باشد.

پیشنهاد حساب جدید ۱۲۸ جریان TCP است. یک گوشی با چند برنامه می‌تواند ده‌ها اتصال هم‌زمان داشته باشد؛ سقف ۱۶ جریان ممکن است با اتصال برنامه‌های پس‌زمینه پر شود. این عدد محدودیت دستگاه نیست. در ارتقا، سقف حساب‌های موجود خودکار تغییر نمی‌کند؛ در صورت نیاز آن را از ویرایش حساب افزایش دهید.

پس از ذخیره، «لینک / QR» را باز کنید. لینک را در Import نسخهٔ فعلی WhiteDNS وارد کنید. تمام دستگاه‌هایی که همان لینک را دارند از یک بودجه استفاده می‌کنند. دامنه و کلید برای هر حساب مستقل‌اند؛ در صورت افشای لینک، «تعویض لینک و کلید» را بزنید و لینک جدید را بدهید.

پس از اتصال، وب‌سایت را باز کنید و IP خروجی را بررسی کنید. با تغییر حجم یا غیرفعال‌کردن حساب در پنل، محدودیت روی سرور اعمال می‌شود؛ اپ را به‌روزرسانی نمی‌کنید. رسیدن به حجم، انقضا یا غیرفعال‌سازی جریان‌های باز را می‌بندد؛ در کلاینت ممکن است صرفاً خطای اتصال دیده شود، نه پیغام اختصاصی تمام شدن حجم.

Resolver ثابت در همهٔ کشورها تضمین‌شده نیست. تنظیم پیش‌فرض کشف مسیر ایران فعال است و دو Resolver فقط نقطهٔ شروع‌اند. اگر شبکه‌ای هیچ مسیر DNS قابل عبور نداشته باشد، پنل این محدودیت را رفع نمی‌کند. برای تأیید ایران به تست واقعی همان شبکه نیاز داریم.

پیش‌فرض حالت پایدار از beta3، اندازهٔ QName را ۱۰۱ و پاسخ DNS را ۵۱۲ بایت تعیین می‌کند؛ درخواست‌های در حال ارسال و پنجرهٔ هر مسیر محدودند. کشف مسیر با فاصلهٔ ۱۵۰۰ میلی‌ثانیه و یک بررسی هم‌زمان، پس از تأیید یک مسیر سالم از افزودن مسیرهای بیشتر خودداری می‌کند؛ در خرابی مسیر، جست‌وجوی جایگزین همچنان فعال است. این انتخاب به نفع پایداری است و می‌تواند حداکثر سرعت را کاهش دهد.

**پس از ارتقا از beta1 یا beta2، لینک همان حساب را دوباره از پنل بگیرید و در اپ Import کنید.** لینک ذخیره‌شده روی گوشی، تنظیمات جدید سرور را خودکار دریافت نمی‌کند. نیازی به تعویض کلید، صفرکردن مصرف یا نصب APK جدید نیست. حساب و کلید قبلی حفظ می‌شوند.

### تنظیمات پیشرفتهٔ تونل در beta4

از «تنظیمات سرور» می‌توانید ۱۶ پارامتر موتور را تغییر دهید. هر ۲۰ فیلد این صفحه، شامل دامنه، Resolver و پورت‌ها، توضیح فارسی دارند: نشانگر را روی فیلد نگه دارید، با کیبورد روی آن بروید یا علامت «؟» را لمس کنید. Escape یا لمس دوباره راهنما آن را می‌بندد.

- **بسته‌ها:** `SafeQName` طول شروع، `MaxQName` سقف طول پرس‌وجو و `MaxAnswer` سقف پاسخ‌اند؛ تغییرشان روی ظرفیت آپلود/دانلود و احتمال افت بسته اثر دارد. MTU رابط VPN گوشی در این صفحه تغییر نمی‌کند.
- **درخواست‌ها:** `MaxInflight` سقف کلی و `MaxPathWindow` سقف هر مسیر است. `Hold` مهلت نگه‌داشتن پرس‌وجوی بیکار است؛ تأخیر ثابت تمام بسته‌ها نیست.
- **کشف مسیر:** روش UDP/TCP، روشن/خاموش‌بودن کشف، تعداد مسیر سالم موردنظر، هم‌زمانی بررسی و فاصلهٔ افزودن مسیر قابل تغییرند. خاموش‌کردن کشف، اتصال را به Resolverهای دستی محدود می‌کند.
- **جریان‌ها:** تعداد جریان، پنجرهٔ دریافت، بافر ارسال، زمان پایان نشست بیکار و مهلت برقراری اتصال قابل تنظیم‌اند. سقف جریان حساب در سرور مستقل است و همچنان اعمال می‌شود.

سه تنظیم آماده «پایدار»، «متعادل» و «کارایی بیشتر» فقط فرم را پر می‌کنند؛ تا «ذخیرهٔ تنظیمات» را نزنید چیزی تغییر نمی‌کند. حالت‌های با بسته و پنجرهٔ بزرگ‌تر برای آزمایش‌اند و الزاماً سریع‌تر یا پایدارتر نیستند. در ارتقا، حالت پایدار beta3 و حساب‌ها حفظ می‌شوند. فیلدهای ناقص یا خارج از محدوده و طول امن بزرگ‌تر از سقف نام در سرور رد می‌شوند.

این تنظیمات، **پیش‌فرض لینک خروجی همهٔ حساب‌ها** هستند؛ برای پروفایل ذخیره‌شده در گوشی، پس از ذخیره لینک همان حساب را دوباره Import کنید. APK جدید، تعویض کلید یا صفرکردن مصرف لازم نیست. رمزنگاری موتور ثابت است؛ گزینهٔ تغییر الگوریتم یا خاموش‌کردن آن وجود ندارد.

مقایسهٔ واقعی این نسخه و محدودیت نتیجه در [PANEL-TUNING-2026-10-17.fa.md](PANEL-TUNING-2026-10-17.fa.md) ثبت شده است.

### ظاهر و نمودارهای پنل در beta5

در beta7، کنترل «بیشتر» در جدول حساب‌ها با منوی اختصاصی هماهنگ با پنل جایگزین شد؛
فونت وزیرمتن، آیکون‌های یکسان و گزینهٔ حذف جداگانه دارد. با کلیک، کیبورد و لمس
قابل استفاده است و نزدیک لبهٔ صفحه در فضای قابل مشاهده باز می‌شود.

در beta6، دکمهٔ «کپی لینک» روی آدرس HTTP سرور هم لینک را مستقیماً کپی می‌کند.
پیام نتیجه داخل پنجرهٔ لینک و با رنگ خوانا نمایش داده می‌شود. اگر مرورگر کپی را
مسدود کند، پیام خطا و راه جایگزین نمایش داده می‌شود؛ صرف انتخاب متن به‌معنای کپی نیست.

فونت فارسی وزیرمتن همراه پنل و از خود سرور دریافت می‌شود؛ CDN لازم نیست. تم تیره و روشن، صفحهٔ ورود تازه، دکمهٔ نمایش رمز و منوی موبایل در دسترس‌اند. انتخاب تم در همان مرورگر ذخیره می‌شود. برای دیدن ظاهر جدید، صفحه را دوباره بارگذاری کنید؛ پروفایل‌ها و تنظیمات تونل نیاز به تغییر ندارند.

نمودارهای CPU، حافظه، دیسک، جریان‌های باز و نرخ DNS از نمونه‌های واقعی همین نشست مرورگر ساخته می‌شوند. داده هر پنج ثانیه دریافت می‌شود؛ سابقهٔ نمودار، حداکثر ده دقیقه و فقط از زمان بازشدن صفحه است و پس از بارگذاری مجدد از نو شروع می‌شود. دادهٔ ناموجود با خط تیره نمایش داده می‌شود. CPU برای محاسبهٔ اولین درصد به دو نمونه نیاز دارد.

نرخ ارسال/دریافت DNS شامل سربار DNS است و با مجموع آپلود/دانلود حساب‌ها که payload TCP را می‌شمارد تفاوت دارد. جریان‌های TCP و حساب‌های دارای جریان، تعداد دستگاه‌ها نیستند. نمودار خالی یا صفر در نبود ترافیک به معنی دادهٔ ساختگی یا اجرای تست سرعت نیست.

## ۶. معنی آمار و محدودیت‌ها

مصرف، تعداد بایت payload در اتصال TCP خروجی است؛ سربار DNS، بازفرستادن بسته و کل مصرف کارت شبکه یا صورتحساب دیتاسنتر نیست. آپلود پیش از ارسال روی دیسک ثبت می‌شود؛ مقدار ارسال‌نشده در خطای معمول برگردانده می‌شود. در قطع ناگهانی برق، حداکثر یک قطعهٔ ناتمام تا ۳۲ KiB در هر جهت هر جریان ممکن است محافظه‌کارانه مصرف محسوب شود. ثبت مصرف با خاموش/روشن‌شدن صفر نمی‌شود و جریان‌های هم‌زمان نمی‌توانند از سقف مشترک عبور کنند. صفر کردن مصرف، دورهٔ جدید ایجاد می‌کند و اتصال قدیمی مجاز به مصرف از دورهٔ جدید نیست.

سرعت، سقف مشترک payload آپلود/دانلود حساب است، نه تضمین حداقل سرعت. محدودیت جریان TCP، محدودیت تعداد دستگاه نیست. IP ورودی معمولاً متعلق به Resolver است؛ از آن برای شمارش کاربران واقعی استفاده نمی‌کنیم. دامنهٔ تصادفی حساب نقش شناسایی پیکربندی را دارد؛ پروتکل بدون تغییر، احراز هویت رمزیِ مستقل برای شخص/دستگاه فراهم نمی‌کند. دارندهٔ لینک یا کسی که آن را در مسیر DNS یاد بگیرد، می‌تواند سهم همان حساب را مصرف کند.

حد فعلی ۵۱۲ حساب، ۸ نشست Soar برای هر حساب، حداکثر ۱۲۸ جریان هر حساب و سقف سراسری ۲۰۴۸ اتصال در حال برقراری/باز است. این‌ها حدود نرم‌افزارند، نه تضمین ظرفیت VPS کم‌حافظه؛ بار واقعی باید سنجیده شود. پورت‌های خروجی پیش‌فرض ۸۰ و ۴۴۳ هستند. آدرس‌های خصوصی، loopback و مقصدهای metadata با محافظ عمومی Lantern مسدودند.

## ۷. پشتیبان و بازیابی

از صفحهٔ پشتیبان‌گیری، فایل کامل را دریافت کنید. این فایل **محرمانه** است. برای بازیابی آن روی همان نسخهٔ پنل، فایل را به سرور منتقل کنید، سپس با جایگزینی مسیر ورودی واقعی:

```bash
sudo systemctl stop soar-panel
sudo cp -p /var/lib/soar-panel/panel.db /root/soar-panel-before-restore.db
sudo install -o soar-panel -g soar-panel -m 0600 /root/YOUR_BACKUP.db /var/lib/soar-panel/panel.db
sudo systemctl start soar-panel
sudo systemctl status soar-panel --no-pager
```

بازیابی بکاپ قدیمی مصرف را به زمان همان بکاپ برمی‌گرداند؛ این انتخاب مدیریتی است. اگر فایل نامعتبر بود، سرویس را متوقف و فایل `/root/soar-panel-before-restore.db` را به همان روش برگردانید. مسیر `before-restore` را برای هر بار بازیابی منحصربه‌فرد کنید تا نسخهٔ قبلی روی آن نوشته نشود.

برای فراموشی رمز، سرویس را متوقف کنید؛ یک فایل موقت با دسترسی 0600 بسازید و رمز جدید را بدون درج در تاریخچه وارد کنید:

```bash
sudo -i
systemctl stop soar-panel
umask 077
read -r -s -p 'New admin password: ' PANEL_PASSWORD; printf '\n'
printf '%s' "$PANEL_PASSWORD" > /root/soar-panel-password.tmp
unset PANEL_PASSWORD
soar-panel admin-reset --db /var/lib/soar-panel/panel.db --admin admin --password-file /root/soar-panel-password.tmp
rm -f /root/soar-panel-password.tmp
systemctl start soar-panel
exit
```

نام مدیر دلخواه را جایگزین کنید. پایگاه داده هنگام اجرای سرویس قفل است؛ فرمان‌های آفلاین با وجود سرویس فعال خطا می‌دهند. ورودهای مرورگر پس از ری‌استارت معتبر نمی‌مانند.

## ساخت از سورس و آزمون توسعه

```bash
go test ./... -count=1 -timeout 90s
go test -race ./internal/panel -count=1 -timeout 120s
go vet ./...
python3 scripts/build_panel_bundle.py
```

Go مطابق go.mod و اسکریپت انتشار نیاز است؛ بستهٔ نهایی به Go، Node، Python، Docker یا پایگاه دادهٔ خارجی روی سرور نیاز ندارد. آزمون مرورگر در `tests/panel-ui.cjs` است و فقط در محیط توسعه به Playwright نیاز دارد. راهنمای معماری و قراردادهای حسابداری در [PANEL-DESIGN.md](PANEL-DESIGN.md) قرار دارد.

برای آزمون اختیاری مسیر واقعی، `tests/live_web_probe.py` لینک حساب آزمایشی را در فایل JSON با فیلد `link` می‌گیرد. گزینه‌های `--profile`، `--engine` (موتور فعلی WhiteDNS)، `--expected-ip` (IP خروجی سرور) و `--output` الزامی‌اند. حالت پیش‌فرض `exported` تنظیمات لینک را بدون تغییر آزمایش می‌کند: TLS معتبر، IP خروجی و بدنهٔ کامل فایل‌های ثابت، به صورت ترتیبی و موازی بررسی می‌شوند. فایل ورودی و پوشهٔ خروجی شامل اطلاعات اتصال‌اند و باید خصوصی بمانند؛ این آزمون جای تست Full VPN روی اندروید یا شبکهٔ ایران را نمی‌گیرد.
