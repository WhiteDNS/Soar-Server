# نصب قدم‌به‌قدم پنل WhiteDNS با Soar و Cotten — نسخهٔ 0.5.0

این راهنما از آماده‌کردن DNS تا ورود به پنل و اولین اتصال گوشی را توضیح می‌دهد. دستورها را در ترمینال SSH **سرور** اجرا کنید؛ فقط دستور تونل SSH که جداگانه مشخص شده، روی کامپیوتر شما اجرا می‌شود.

## ۱. اطلاعات لازم را آماده کنید

- سرور Ubuntu 22.04/24.04/26.04 یا Debian 12/13، با معماری **amd64 / x86_64** و systemd؛ دسترسی root یا sudo.
- دامنه‌ای که بتوانید رکوردهای DNS آن را تغییر دهید و IP عمومی سرور از پنل شرکت VPS.
- برنامهٔ WhiteDNS روی گوشی؛ برای استفاده از لینک ساب، نسخهٔ **1.6.8 یا جدیدتر** لازم است.

در تمام مراحل از یک مثال ثابت استفاده می‌کنیم:

| اطلاعات | مقدار در مثال |
| --- | --- |
| دامنهٔ اصلی | `example.com` |
| زیردامنهٔ تونل | `soar.example.com` |
| نام نیم‌سرور تونل | `ns-soar.example.com` |
| IP عمومی سرور | `203.0.113.10` |
| دامنهٔ ورود HTTPS به پنل | `panel.example.com` |
| نام مدیر / پورت مدیریت | `admin` / `2053` |

**دامنه‌ها و IP جدول فقط مثال‌اند؛ همه‌جا اطلاعات واقعی خودتان را جایگزین کنید.** آدرس `203.0.113.10` برای مستندات رزرو شده و نصب‌کننده آن را به‌عنوان IP عمومی قبول نمی‌کند. نام تونل، مانند `soar.example.com`، باید حداکثر ۲۴ نویسه باشد.

## ۲. رکوردهای DNS و فایروال را آماده کنید

در پنل DNS دامنهٔ اصلی، این رکوردها را بسازید:

| نوع | Name / نام | Value / مقدار | وضعیت پراکسی |
| --- | --- | --- | --- |
| A | `ns-soar` | IP عمومی واقعی سرور | خاموش / DNS only |
| NS | `soar` | `ns-soar.example.com` | — |
| A | `panel` | IP عمومی واقعی سرور | خاموش / DNS only |

اگر پنل DNS نام کامل می‌خواهد، به‌ترتیب `ns-soar.example.com`، `soar.example.com` و `panel.example.com` را بنویسید. رکورد سوم برای HTTPS پنل است؛ دو رکورد اول برای تونل‌اند. برای هر حساب کاربری رکورد جداگانه نسازید.

برای `soar` نام تازه‌ای انتخاب کنید که سرویس دیگری از آن استفاده نکند. رکوردهای سایت، ایمیل، MasterDNS یا Cotton را تغییر ندهید.

در فایروال پنل VPS، ورودی‌های زیر را مجاز کنید:

| پورت ورودی | کاربرد |
| --- | --- |
| `UDP/53` و `TCP/53` | اتصال تونل‌های Soar و Cotten |
| `TCP/2053` | ورود مستقیم اولیه به پنل، در روش این مثال |
| `TCP/80` و `TCP/443` | دریافت گواهی و ورود HTTPS به پنل |

اگر سرور پشت NAT است، همین پورت‌ها باید به IP محلی سرور هدایت شوند. دسترسی SSH فعلی را حفظ کنید. برای HTTPS داخلی، پورت‌های ۸۰ و ۴۴۳ باید آزاد باشند؛ اگر وب‌سرور دیگری آن‌ها را گرفته، از روش خصوصی SSH در بخش ۷ استفاده کنید.

## ۳. نصب‌کننده را اجرا کنید

با SSH وارد سرور شوید. اگر کاربر شما root نیست، ابتدا اجرا کنید:

```bash
sudo -i
```

نصب‌کننده پورت‌های لازم را در UFW فعال خودکار باز می‌کند؛ هنگام فعال‌سازی HTTPS هم پورت‌های ۸۰ و ۴۴۳ خودکار آماده می‌شوند. فقط فایروال و NAT پنل شرکت VPS را مطابق جدول بالا تنظیم کنید.

اگر `curl` نصب نیست:

```bash
apt-get update
apt-get install -y curl
```

سپس نصب‌کنندهٔ پنل را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/WhiteDNS/Soar-Server/main/panel-setup.sh)
```

هر پاسخ را بنویسید و Enter بزنید. مقدار داخل `[...]` پیش‌فرض است؛ Enter خالی آن را انتخاب می‌کند. پیام‌های `[OK]` و گزارش پیشرفت پاسخ نمی‌خواهند.

اگر ابزارهای لازم نصب نباشند، این پرسش را می‌بینید:

| پیام ترمینال | چه وارد کنید؟ |
| --- | --- |
| `Install these packages using apt-get? (Y/n) [Y]:` | `Y` یا فقط Enter؛ منتظر پایان نصب بسته‌ها بمانید. |

## ۴. به پرسش‌های نصب پاسخ بدهید

### مرحلهٔ ۱ از ۷: بررسی سرور

این مرحله خودکار است و چیزی وارد نمی‌کنید. اگر خطای اشغال‌بودن `UDP/53` یا `TCP/53` دیدید، سرویس دیگری روی آدرس انتخاب‌شده فعال است؛ برای نصب ساده از VPS جداگانه استفاده کنید.

### مرحلهٔ ۲ از ۷: اطلاعات DNS و IP

پیش‌فرض‌های جدول برای مثال همین راهنما هستند؛ روی سرور شما IP و دامنه فرق می‌کنند. `[...]` یعنی پیش‌فرض وابسته به سرور شماست و ممکن است نمایش داده نشود.

| پیام ترمینال | پاسخ در مثال |
| --- | --- |
| `Tunnel subdomain (example: soar.example.com, max 24 characters):` | `soar.example.com` |
| `Main DNS zone you can edit [example.com]:` | `example.com` یا Enter |
| `Nameserver hostname (inside the main zone, outside the tunnel) [ns-soar.example.com]:` | `ns-soar.example.com` یا Enter |
| `Local IPv4 for the DNS listener (behind NAT, use the local IP) [...]:` | IP روی کارت شبکهٔ سرور؛ اگر مقدار پیشنهادی درست است، Enter. |
| `PUBLIC IPv4 from your VPS provider (the A record value) [...]:` | IP عمومی واقعی VPS؛ در مثال `203.0.113.10`. |
| `Resolvers for server-side DNS and tunnel tests [1.1.1.1,8.8.8.8]:` | Enter؛ یا `1.1.1.1,8.8.8.8` بدون فاصله. |
| `Public IP or SSH hostname for access instructions [...]:` | IP یا نامی که با آن SSH می‌زنید؛ در مثال IP عمومی سرور. بدون `http://` و بدون پورت. |

نصب‌کننده فهرست IPهای سرور را نشان می‌دهد. روی VPS معمولی ممکن است IP عمومی روی کارت شبکه هم باشد؛ پشت NAT، مثلاً `10.0.0.2` را برای Local IPv4 و IP عمومی شرکت VPS را برای PUBLIC IPv4 وارد کنید. رکورد A باید به IP عمومی اشاره کند. در نصب مجدد، همان زیردامنهٔ تونل قبلی را وارد کنید.

سپس A و NS بررسی می‌شوند. در نصب تازه، لازم نیست خود سرویس Soar از قبل پاسخ DNS بدهد. اگر بررسی شکست خورد، بخش «اگر نصب متوقف شد» را بخوانید.

### مرحلهٔ ۳ از ۷: حساب مدیر

| پیام ترمینال | چه وارد کنید؟ |
| --- | --- |
| `Administrator name [admin]:` | `admin` یا Enter |
| `New administrator password:` | رمز اختصاصی خودتان، ۱۲ تا ۷۲ نویسهٔ قابل چاپ انگلیسی؛ مثل `My-Own-Pass-42!`، ولی **از همین رمز نمونه استفاده نکنید**. |
| `Repeat password:` | دقیقاً همان رمز قبلی |

هنگام تایپ رمز، هیچ حرف یا ستاره‌ای نمایش داده نمی‌شود؛ طبیعی است. نام مدیر و رمز را ذخیره کنید. اگر پنل قبلاً نصب بوده، این پرسش‌ها نمایش داده نمی‌شوند و رمز قبلی باقی می‌ماند.

### مرحلهٔ ۴ از ۷: روش ورود و پورت

| پیام ترمینال | پاسخ در مسیر این مثال |
| --- | --- |
| `Access mode (1 or 2) [1]:` | `1`؛ دسترسی مستقیم اولیه، سپس فعال‌کردن HTTPS در پایان نصب. |
| `Management TCP port [2053]:` | `2053` یا Enter؛ اگر اشغال بود، مثلاً `2054` و همان پورت را در فایروال VPS باز کنید. |

گزینهٔ `1` ابتدا HTTP بدون رمزگذاری می‌دهد؛ در ادامهٔ این مثال، پیش از ورود با رمز مدیر، HTTPS را فعال می‌کنیم. اگر HTTPS را فعلاً راه نمی‌اندازید، از ابتدا گزینهٔ `2` را برای ورود خصوصی با SSH انتخاب کنید؛ دستور اتصال در بخش ۷ آمده است.

### مرحلهٔ ۵ از ۷: تأیید نهایی

خلاصهٔ دامنه، IP و پورت را بخوانید، سپس:

| پیام ترمینال | چه وارد کنید؟ |
| --- | --- |
| `Type INSTALL to install/start this panel, or anything else to cancel:` | دقیقاً `INSTALL` با حروف بزرگ |
| `Type MIGRATE to accept this migration, or anything else to cancel:` | فقط اگر از Soar بدون پنل مهاجرت می‌کنید: دقیقاً `MIGRATE` |

پرسش دوم جایگزین اول است و فقط برای سرویس قدیمی نمایش داده می‌شود. مهاجرت، سرویس قدیمی را متوقف می‌کند و **لینک‌های قبلی آن در پنل کار نمی‌کنند**؛ باید حساب و لینک جدید بسازید. اگر قصد مهاجرت ندارید، Enter بزنید تا لغو شود.

### مرحلهٔ ۶ از ۷: نصب و آزمایش اتصال

منتظر بمانید؛ در حالت موفق چیزی وارد نمی‌کنید. نصب‌کننده سرویس و عبور واقعی ترافیک از تونل را آزمایش می‌کند. اگر منوی خطا ظاهر شد، مطابق بخش انتهای راهنما عمل کنید.

در مرحلهٔ بررسی اتصال، آزمون‌های Soar و Cotten خودکار اجرا می‌شوند. Cotten هم روی UDP و هم TCP آزمایش می‌شود؛ چیزی وارد نکنید و تا پایان بررسی منتظر بمانید.

### مرحلهٔ ۷ از ۷: آدرس پنل و پرسش HTTPS

آدرس کامل نمایش‌داده‌شده را ذخیره کنید. آدرس شامل مسیر تصادفی ورود است؛ فقط بازکردن IP و پورت کافی نیست.

| پیام ترمینال | پاسخ در مسیر این مثال |
| --- | --- |
| `Open the optional domain/HTTPS setup now? [y/N]:` | `y`؛ اگر رکورد `panel` و پورت‌های ۸۰/۴۴۳ آماده نیستند، `n`؛ پس از آماده‌سازی، دستور بخش ۵ را اجرا کنید. |

## ۵. HTTPS پنل را فعال کنید

اگر در پرسش قبل `y` زده‌اید، همین حالا پرسش‌های زیر نمایش داده می‌شوند. اگر `n` زده‌اید، پس از آماده‌کردن رکورد `panel` و پورت‌ها، در SSH با دسترسی root اجرا کنید:

```bash
soar-panel-security
```

| پیام ترمینال | پاسخ در مثال |
| --- | --- |
| `Choose [1]:` | `1` یا Enter؛ تنظیم دامنه و HTTPS. |
| `Panel domain (leave empty to keep the existing domain, or use only a random path):` | `panel.example.com`؛ دامنهٔ واقعی پنل، بدون `https://` و بدون مسیر. |
| `Certificate account email (optional):` | ایمیل خودتان، مثلاً `you@example.com`؛ یا Enter برای خالی‌گذاشتن. |
| `Generate a new random login path? [Y/n]:` | `Y` یا Enter |
| `Type APPLY to continue:` | دقیقاً `APPLY`؛ با ادامه، شرایط سرویس گواهی Let's Encrypt را می‌پذیرید. |

منتظر دریافت گواهی و راه‌اندازی مجدد بمانید. **آدرس نهایی جدید**، مانند `https://panel.example.com/مسیر-تصادفی/`، را کامل ذخیره و در مرورگر باز کنید؛ مسیر را خودتان از روی مثال نسازید. نام مدیر و رمز همان مرحلهٔ ۳ است.

اگر HTTPS خطا داد، تنظیم دسترسی قبلی بازگردانده می‌شود. A دامنهٔ `panel`، رکورد AAAA اشتباه، پراکسی خاموش، بازبودن پورت‌ها و اشغال‌نبودن ۸۰/۴۴۳ را بررسی و دستور بالا را دوباره اجرا کنید.

## ۶. اولین حساب را بسازید و گوشی را وصل کنید

1. آخرین نسخهٔ اپ WhiteDNS را روی گوشی نصب کنید و با نام مدیر و رمز نصب وارد پنل شوید.
2. «حساب‌های کاربری» ← «حساب جدید» را بزنید. مثلاً نام `test-phone` و حجم `1` GiB را وارد کنید. گزینهٔ «موتور اتصال» را روی **Soar و Cotten (پیشنهادی)** بگذارید؛ سایر گزینه‌ها می‌توانند همان پیش‌فرض باشند.
3. حساب را ذخیره کنید و برای همان حساب «لینک / QR» ← **«لینک ساب»** را باز کنید. لینک را کپی کنید یا QR آن را با WhiteDNS بخوانید.
4. لینک ساب را در WhiteDNS وارد کنید. دو پروفایل دریافت می‌کنید: یکی برای Soar و یکی با نام Cotten. یکی را انتخاب و متصل کنید؛ اگر روی شبکهٔ شما جواب نداد، دیگری را امتحان کنید. اپ با واردکردن ساب، خودکار بین دو موتور جابه‌جا نمی‌شود.
5. یک وب‌سایت باز کنید و IP خروجی را بررسی کنید؛ باید IP سرور باشد. حجم و تاریخ انقضا بین هر دو پروفایل مشترک است.

**برای Cotten هیچ دامنه، رکورد DNS، کلید یا دستور نصب جداگانه‌ای لازم نیست.** همه را پنل می‌سازد. در همان پنجره، دکمه‌های «Soar» و «Cotten» لینک مستقیم هر موتور را هم می‌دهند؛ اگر فقط یکی را می‌خواهید، می‌توانید همان را وارد کنید.

حساب‌های قدیمی همچنان Soar هستند و لینکشان حفظ می‌شود. برای افزودن Cotten، حساب را ویرایش کنید، «موتور اتصال» را روی «Soar و Cotten» بگذارید و سپس ساب آن حساب را در گوشی تازه‌سازی کنید.

## ۷. ورود خصوصی با SSH، اگر HTTPS را فعلاً نمی‌خواهید

در مرحلهٔ ۴، `Access mode` را `2` انتخاب کنید و به پرسش پایانی HTTPS پاسخ `n` بدهید. سپس **روی کامپیوتر خودتان**، در ترمینال جدا اجرا کنید؛ IP و در صورت تغییر، پورت را جایگزین کنید:

```bash
ssh -N -L 2053:127.0.0.1:2053 root@203.0.113.10
```

اگر SSH رمز می‌خواهد، رمز **ورود به سرور** را وارد کنید؛ این رمز با رمز مدیر پنل فرق دارد. اگر با کاربری غیر از root وارد سرور می‌شوید، همان نام کاربر را به‌جای `root` بنویسید. برای SSH روی پورت غیرپیش‌فرض، مثلاً ۲۲۲۲، گزینهٔ `-p 2222` را به دستور اضافه کنید.

ترمینال را باز نگه دارید و آدرس کامل محلی چاپ‌شده در پایان نصب، مانند `http://127.0.0.1:2053/مسیر-تصادفی/`، را در مرورگر همان کامپیوتر باز کنید. در این روش نیازی به بازکردن عمومی TCP/2053 نیست.

## اگر نصب متوقف شد، چه وارد کنم؟

### خطای بررسی DNS، پیش از تأیید نصب

با پیام `No service changes yet`، پرسش `Choose [1]:` و چهار گزینه نمایش داده می‌شود:

| پاسخ | چه زمانی انتخاب کنید؟ |
| --- | --- |
| `1` یا Enter | A و NS را اصلاح کرده‌اید؛ بعد از انتشار رکوردها دوباره بررسی شود. |
| `2` | دامنه یا IP را اشتباه وارد کرده‌اید؛ پرسش‌های مرحلهٔ ۲ دوباره نمایش داده شوند. |
| `3` | Resolverهای فعلی از سرور در دسترس نیستند؛ فهرست Resolver دیگری وارد کنید. |
| `4` | لغو نصب؛ هنوز سرویس‌ها تغییر نکرده‌اند. |

در گزینهٔ `3`، پیام `Resolver IPv4s, separated by commas [...]:` را می‌بینید؛ مثلاً `1.1.1.1,8.8.8.8` را **بدون فاصله** وارد کنید، به‌شرط آنکه از سرور شما در دسترس باشند. اگر همین فهرست از قبل ناموفق بوده، Resolver قابل‌دسترس دیگری انتخاب یا مشکل دسترسی DNS سرور را رفع کنید.

برای خطای رکورد، A و NS بخش ۲ را با خروجی نصب‌کننده تطبیق دهید: A باید IP عمومی باشد، پراکسی خاموش باشد و روی نام تونل، رکورد یا واگذاری متعارض وجود نداشته باشد.

### خطای آزمایش اتصال، پس از شروع سرویس

در این مرحله نیز `Choose [1]:` نمایش داده می‌شود، اما معنی گزینه‌ها متفاوت است:

| پاسخ | نتیجه |
| --- | --- |
| `1` یا Enter | پس از اصلاح DNS، فایروال یا NAT، آزمایش تکرار می‌شود. |
| `2` | با پیام `Test resolver IPv4s, separated by commas [...]:` فهرست Resolver قابل‌دسترس دیگری وارد می‌کنید؛ قالب همان `1.1.1.1,8.8.8.8` بدون فاصله است. |
| `3` | نصب تأییدنشده باقی می‌ماند؛ در پرسش `Type KEEP to retain the installation with checks pending:` باید دقیقاً `KEEP` بزنید. این گزینه به معنی کارکردن کانفیگ نیست. |
| `4` | نصب برگردانده می‌شود. |

برای نصب قابل استفاده، مشکل را رفع و گزینهٔ `1` را انتخاب کنید؛ اگر نمی‌توانید رفع کنید، `4` را بزنید. بازبودن UDP/53 و TCP/53 در پنل VPS و هدایت NAT را حتماً بررسی کنید.

### آدرس ورود را پیدا نمی‌کنم

در SSH با دسترسی root، دستور `soar-panel-security` را اجرا و در `Choose [1]:` عدد `2` را وارد کنید تا آدرس فعلی نمایش داده شود. مسیر تصادفی انتهای آدرس را حذف نکنید.

برای افزودن دامنهٔ جایگزین اتصال یا آدرس دوم پنل پس از نصب، [راهنمای دامنه‌ها](DOMAINS.fa.md) را ببینید. این کار حساب و سهمیهٔ کاربران را حفظ می‌کند.
