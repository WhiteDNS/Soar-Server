# مسیر خروجی موتورها و گزارش ترافیک

این راهنما برای **پنل 0.14.0 و جدیدتر** است؛ نسخهٔ 0.13.0 این گزینه‌ها را ندارد.
[راهنمای اصلی پنل](PANEL.fa.md) · [English](EGRESS.en.md) · [دانلود 0.14.0](https://github.com/WhiteDNS/Soar-Server/releases/tag/panel-v0.14.0)

## ۱. پیش از شروع و به‌روزرسانی

1. از «پشتیبان و بازیابی» یک بکاپ بگیرید و آن را خصوصی نگه دارید.
2. اگر هنوز نسخهٔ قدیمی دارید، در بخش به‌روزرسانی پنل، نسخهٔ پایدار را بررسی و نصب کنید؛ سپس صفحهٔ مرورگر را دوباره بارگذاری کنید. برای نصب اولیه از دستور [راهنمای اصلی](PANEL.fa.md) استفاده کنید.
3. پراکسی موردنظر را جداگانه آماده کنید. پنل یک ورودی SOCKS5 یا HTTP CONNECT موجود را مصرف می‌کند؛ لینک اشتراک، لینک VLESS/VMess و فایل کانفیگ Xray در این فیلد پذیرفته نمی‌شود.
4. اگر ورودی روی همین سرور است، آدرس لوکال و پورت واقعی آن را از تنظیمات همان سرویس پیدا کنید؛ `127.0.0.1:1080` فقط مثال است. نیازی به عمومی‌کردن پورت این ورودی لوکال نیست.
5. تنظیمات خروجی هر موتور برای همهٔ حساب‌هایی که از همان موتور استفاده می‌کنند اعمال می‌شود؛ این بخش پراکسی جداگانه برای هر حساب تعریف نمی‌کند.

برای رفتن به بخش موردنظر:

| کار | مسیر فارسی | مسیر انگلیسی |
| --- | --- | --- |
| پراکسی، پورت‌های Upstream و فعال‌کردن ثبت | تنظیمات سرور ← پراکسی خروجی و گزارش ترافیک | Server settings → Upstream proxies & traffic reports |
| مشاهده، فیلتر و دانلود گزارش | لاگ‌ها و دستیار ← گزارش ترافیک خروجی | Logs & assistant → Outbound traffic report |

## ۲. تنظیم قدم‌به‌قدم یک پراکسی لوکال

فرض کنید Xray یا sing-box از قبل یک ورودی **SOCKS5 روی `127.0.0.1:1080`** دارد و قوانین خروجی همان سرویس نیز تنظیم شده‌اند:

1. «تنظیمات سرور» و سپس کارت «پراکسی خروجی و گزارش ترافیک» را باز کنید.
2. در کادر موتور موردنظر، مثلاً **Soar**، «مسیر» را روی **SOCKS5** بگذارید.
3. «آدرس پراکسی» را `127.0.0.1:1080` وارد کنید؛ `socks5://`، مسیر URL و اطلاعات ورود را به آدرس اضافه نکنید.
4. اگر ورودی احراز هویت دارد، **هم نام کاربری و هم رمز** را در فیلدهای جدا وارد کنید. اگر ندارد، هر دو را خالی بگذارید.
5. برای شروع، «پورت‌های مجاز روی پراکسی» را `80,443` بگذارید؛ برای نیازهای دیگر، بخش پورت‌ها را بخوانید.
6. برای **Cotten و MasterDNS** هم مسیر دلخواه را جدا انتخاب کنید. برای عبور هر سه موتور از یک پراکسی، باید همین آدرس را در هر سه کادر وارد کنید. تغییر Soar دو موتور دیگر را تغییر نمی‌دهد؛ CottenMax از تنظیم Cotten استفاده می‌کند.
7. در صورت نیاز به گزارش مقصدها، گزینهٔ «ثبت گزارش خروجی فعال باشد» را بزنید و زمان و سقف فضای نگهداری را تعیین کنید.
8. «ذخیرهٔ مسیر خروجی» را بزنید و منتظر پیام موفقیت بمانید. اتصال‌های فعلی موتورهای فعال قطع و موتور با تنظیم جدید راه‌اندازی می‌شود؛ یک بازهٔ کوتاه قطع اتصال طبیعی است.
9. از اپ WhiteDNS با یک حساب آزمایشی، هر موتور را جداگانه وصل و یک سایت HTTPS باز کنید. IP خروجی را از داخل همان اتصال بررسی و با خروجی مورد انتظار پراکسی مقایسه کنید. آزمون مرورگر خود سرور، مسیر کاربر تونل را ثابت نمی‌کند.

تغییر Upstream به ساخت دوبارهٔ حساب یا واردکردن مجدد لینک ساب نیاز ندارد. برای آزمون مسیر جدید، اتصال قبلی اپ را قطع و دوباره وصل کنید. اگر تازه موتور دیگری را به حساب اضافه کرده‌اید، ساب را هم تازه‌سازی کنید.

نمونهٔ تفکیک مسیرها:

| موتور | مسیر | آدرس نمونه | پورت مقصد مجاز |
| --- | --- | --- | --- |
| Soar | SOCKS5 | `127.0.0.1:1080` | `80,443` |
| Cotten / CottenMax | HTTP CONNECT | `127.0.0.1:8080` | `80,443,8443` |
| MasterDNS | مستقیم | ندارد | فهرست مستقیم تنظیمات سرور |

این‌ها پورت‌های نمونه‌اند؛ وجود سرویس روی آن‌ها را فرض نکنید. یک ورودی HTTP را با نوع SOCKS5 انتخاب نکنید، حتی اگر شمارهٔ پورت آن مشابه مثال باشد.

## ۳. آدرس، رمز و رفتار ذخیره

در «تنظیمات سرور ← پراکسی خروجی و گزارش ترافیک»، مسیر Soar، Cotten و
MasterDNS را مستقل انتخاب کنید. حالت CottenMax از مسیر Cotten استفاده می‌کند.
تغییر معتبر تنظیمات، موتورهای فعال را کوتاه‌مدت دوباره راه‌اندازی می‌کند؛ حساب،
کلید، دامنه، ساب و مصرف حفظ می‌شود. تنظیم نامعتبر ذخیره نمی‌شود و موتورهای
درحال اجرا را متوقف نمی‌کند.

### نوع اتصال به پراکسی

- مستقیم: همان فهرست پورت‌های مجاز تنظیمات سرور اعمال می‌شود.
- SOCKS5: اتصال TCP و UDP ASSOCIATE، با یا بدون نام کاربری و رمز.
- HTTP CONNECT: فقط TCP؛ UDP پشتیبانی‌نشده رد می‌شود.
- HTTPS CONNECT: همان CONNECT، همراه با بررسی معتبر گواهی و نام میزبان پراکسی.

برای UDP، آدرس relay باید IP همان اتصال پراکسی یا آدرس نامشخصِ آن باشد؛ relay
روی میزبان دیگری پذیرفته نمی‌شود. HTTP از احراز هویت Basic استفاده می‌کند.

مثلاً برای یک ورودی SOCKS5 در Xray یا sing-box روی همین سرور، حالت SOCKS5
و آدرس `127.0.0.1:1080` را انتخاب کنید. آدرس باید `HOST:PORT` باشد؛ نام
کاربری و رمز فیلد جدا دارند. رمز ذخیره‌شده نمایش داده نمی‌شود. خالی گذاشتن
رمز فقط وقتی آن را حفظ می‌کند که نوع پراکسی، آدرس و نام کاربری عوض نشده باشند.
برای حذف احراز هویت، گزینهٔ مربوط را انتخاب کنید.

قطع پراکسی، شکست احراز هویت یا پشتیبانی‌نشدن UDP باعث خروج مستقیم نمی‌شود.
ابتدا پراکسی را روی سرور آماده کنید. تعیین خروجی نهایی WARP، Psiphon یا
سرویس دیگر بر عهدهٔ قوانین همان هسته است؛ صرف اتصال به پراکسی لوکال، استفاده
از خروجی جایگزین را اثبات نمی‌کند. پنل آن هسته‌ها را نصب یا پیکربندی نمی‌کند.

SOCKS5 و HTTP معمولی احراز هویت را رمزگذاری نمی‌کنند. برای پراکسی راه دور،
HTTPS یا یک مسیر شبکهٔ مورد اعتماد به کار ببرید. گواهی نامعتبر پذیرفته نمی‌شود.

آدرس معتبر به شکل `HOST:PORT` است؛ مثلاً `proxy.example.com:443` یا برای IPv6، `[::1]:1080`. در HTTPS CONNECT، گواهی باید با نام میزبان یا IP واردشده معتبر باشد؛ این حالت به‌معنی فعال‌کردن HTTPS پنل نیست و گواهی پراکسی را صادر نمی‌کند. نام دامنهٔ نمونه را با پراکسی واقعی خودتان جایگزین کنید.

پس از ذخیره، خالی بودن فیلد رمز به‌معنی پاک‌شدن آن نیست. برای حفظ رمز، پروتکل، آدرس و نام کاربری را تغییر ندهید. پس از تغییر هرکدام، رمز را دوباره وارد کنید. برای حذف ورود ذخیره‌شده، «حذف احراز هویت ذخیره‌شده» را انتخاب کنید؛ برای عوض‌کردن رمز، رمز جدید را بنویسید و گزینهٔ حذف را نزنید. اگر پیام دریافت دوبارهٔ تنظیمات یا تعارض دیدید، صفحه را تازه‌سازی، تنظیم فعلی را بررسی و تغییر را دوباره اعمال کنید.

## ۴. پورت‌ها، مقصدها و DNS

برای مسیر پراکسی، فهرست یا بازه‌هایی مانند `80,443,1000-2000` وارد کنید، یا
«بدون محدودیت پورت روی پراکسی» را فعال کنید. این استثنا هرگز فهرست پورت‌های
خروج مستقیم را باز نمی‌کند. Anti-Flood، سهمیه و سقف اتصال در مسیر پراکسی هم
اعمال می‌شوند؛ ردیابی مقصد بر اساس IP نهایی است، نه IP مشترک پراکسی.

| مقدار | نتیجه |
| --- | --- |
| `80,443` | فقط این دو پورت مقصد از مسیر همان پراکسی |
| `1-2000` | همهٔ پورت‌های مقصد از ۱ تا ۲۰۰۰، شامل دو انتها |
| `80,443,1000-2000,8443` | ترکیب پورت تکی و بازه |
| «بدون محدودیت پورت روی پراکسی» | برداشتن فیلتر پورت برای همان مسیر پراکسی؛ سایر محدودیت‌ها برقرارند |

**پورت ورودی پراکسی با پورت مقصد فرق دارد.** در `127.0.0.1:1080`، عدد ۱۰۸۰ پورت ورودی پراکسی است؛ برای بازکردن یک سایت روی ۴۴۳، عدد ۴۴۳ باید در فهرست مقصد باشد. بازهٔ `1-2000` پورت ۸۴۴۳ را شامل نمی‌شود. پورت‌های معتبر ۱ تا ۶۵۵۳۵ هستند؛ بازهٔ برعکس، مثل `2000-1`، رد می‌شود. در حالت مستقیم، این فیلد و گزینهٔ پورت آزاد غیرفعال‌اند و فهرست اصلی تنظیمات سرور اعمال می‌شود.

برداشتن محدودیت پورت، پشتیبانی پروتکل جدید ایجاد نمی‌کند: HTTP CONNECT همچنان UDP را رد می‌کند و افزودن SOCKS5 نیز قابلیت انتقال UDP دلخواه را به کلاینت یا موتوری که آن را ندارد اضافه نمی‌کند. برای نمونه، MasterDNS همچنان انتقال TCP روی DNS دارد.

دسترسی به مقصدهای داخلی، لوپ‌بک، link-local و آدرس‌های ممنوع همچنان مسدود است.
اجازهٔ اتصال داخلی فقط برای نقطهٔ پراکسیِ مشخص‌شده توسط مدیر است. IP نهایی پس
از بررسی ثابت می‌ماند؛ پراکسی مقصد را به شکل IP دریافت می‌کند. قوانین مبتنی
بر دامنه در هستهٔ بعدی باید با این رفتار هماهنگ باشند؛ ارسال دوبارهٔ نام مقصد
برای دور زدن بررسی IP انجام نمی‌شود.

جست‌وجوی نام مقصد از DNS روی TCP و همان مسیر پراکسی موتور عبور می‌کند.
DNS تونل Cotten و MasterDNS نیز از همان مسیر می‌رود؛ HTTP از TCP به جای UDP
استفاده می‌کند. Resolverها از فهرست تنظیم‌شده و جایگزین‌های عمومی فعلی پنل
انتخاب می‌شوند. پراکسی باید اتصال به پورت Resolver را اجازه دهد.

اتصال‌های داخلی Resolver فقط به endpointهای Resolver مجاز پنل استثنا دارند. برای DNS داخلی پنل لازم نیست صرفاً به همین دلیل پورت ۵۳ را برای تمام مقصدهای کاربران باز کنید؛ در خود پراکسی و فایروال مسیر، دسترسی به Resolver را بررسی کنید.

اگر آدرس خود پراکسی نام دامنه باشد، پیدا کردن IP آن به DNS راه‌اندازی سرور
نیاز دارد. استفاده از IP در فیلد آدرس پراکسی، این نیاز را حذف می‌کند. درخواست
کاربر به مقصدهای خصوصی حتی از پشت پراکسی پذیرفته نمی‌شود.

## ۵. فعال‌کردن ثبت و دریافت گزارش

1. در «تنظیمات سرور ← پراکسی خروجی و گزارش ترافیک»، «ثبت گزارش خروجی فعال باشد» را فعال کنید.
2. مقدار اولیهٔ نگهداری **۲۴ ساعت** و سقف فضا **۳۲ MiB** است؛ متناسب با ترافیک سرور تنظیم کنید و «ذخیرهٔ مسیر خروجی» را بزنید. این ذخیره هم موتورهای فعال را دوباره راه‌اندازی می‌کند.
3. بعد از فعال‌شدن ثبت، اتصال آزمایشی موردنظر را دوباره برقرار کنید. رخدادهای پیش از فعال‌شدن ثبت بازسازی نمی‌شوند.
4. «لاگ‌ها و دستیار» و کارت «گزارش ترافیک خروجی» را باز کنید.
5. «از تاریخ و ساعت» و «تا تاریخ و ساعت» را دقیق، همراه ساعت، دقیقه و در صورت نیاز ثانیه تنظیم کنید؛ پایان باید مساوی یا بعد از شروع باشد.
6. موتور، مسیر و وضعیت را انتخاب کنید. برای همهٔ نتایج، فیلترهای مربوط را روی «همه» بگذارید. «شناسهٔ حساب» اختیاری است و ID دقیق می‌خواهد؛ نام نمایشی حساب نیست. می‌توانید ID را از یک ردیف گزارش یا خروجی قبلی بردارید.
7. «نمایش گزارش» را بزنید. با تغییر فیلتر، دوباره همین دکمه را بزنید؛ سپس از «صفحهٔ قبل / بعد» استفاده کنید. جدول هر صفحه تا ۲۰۰ ردیف دارد.
8. برای نتایج تازه‌تر، زمان پایان را جلو ببرید و گزارش را دوباره نمایش دهید؛ بازهٔ اولیهٔ یک‌ساعته یک انتخاب اولیه است، نه پنجرهٔ زنده و پیوسته.
9. «دانلود CSV» یا «دانلود JSON» را بزنید. دانلود از مقادیر فعلی فرم استفاده می‌کند؛ برای یکسان‌بودن جدول و فایل، ابتدا همان فیلترها را با «نمایش گزارش» اعمال کنید.

### چه چیزی ثبت می‌شود؟

ثبت مقصدها برای حفظ حریم خصوصی، پیش‌فرض خاموش است. با فعال‌کردن آن، در
«لاگ‌ها و دستیار ← گزارش ترافیک خروجی» اطلاعات زیر در دسترس است:

- موتور و شناسهٔ حساب، مقصد درخواستی، IP بررسی‌شده و پورت؛
- TCP یا UDP، ترافیک کاربردی یا DNS، مسیر و نقطهٔ پراکسی بدون رمز؛
- زمان شروع، پایان و آخرین مشاهده، تلاش‌های اتصال و علت شکست یا رد؛
- بایت‌های payload رفت و برگشت و وضعیت اتصال.

متن درخواست، محتوای ترافیک، پرس‌وجوی DNS و رمز پراکسی ثبت نمی‌شود. این داده‌ها
خودکار وارد زمینهٔ دستیار هوش مصنوعی نمی‌شوند. لاگ تشخیصی قبلی نیز جدا و بدون
مقصد باقی می‌ماند. گزارش مقصد فقط برای مدیر واردشده قابل مشاهده و دانلود است.

از تاریخ و ساعت شروع و پایان دلخواه استفاده کنید. زمان ورودی به وقت دستگاه
مدیر است و خروجی CSV زمان UTC دارد. بازه، **شروع اتصال** را فیلتر می‌کند؛ حجم
هر ردیف کل payload آن اتصال است و صرفاً حجم بخش داخل بازه نیست. این گزارش
شمارندهٔ درخواست HTTP یا ضبط محتوای رمزگشایی‌شده نیست. حجم ممکن است با سهمیهٔ
حساب و حجم روی سیم تفاوت داشته باشد؛ سربار DNS و پروتکل پراکسی جزو آن نیست.

جدول صفحه‌بندی دارد؛ CSV و JSON همهٔ رکوردهای باقی‌ماندهٔ منطبق با فیلترها را
در یک snapshot می‌دهند. بیش از ۱۰۰ هزار اتصال در یک گزارش پذیرفته نمی‌شود؛
بازهٔ کوچک‌تری انتخاب کنید. برای جلوگیری از فشار دائمی، جدول خودکار بازخوانی
نمی‌شود.

### معنی بازه و حجم؛ یک مثال

اگر بازه را ۱۰:۰۰ تا ۱۱:۰۰ انتخاب کنید، اتصالی که ۰۹:۵۹ شروع شده و تا ۱۰:۳۰ باز بوده در نتیجه نمی‌آید؛ اتصال شروع‌شده در ۱۰:۱۰ می‌آید و حجم ثبت‌شدهٔ **کل آن اتصال** گزارش می‌شود، حتی اگر بعد از ۱۱:۰۰ هم ادامه داشته باشد. برای تطبیق گزارش دیتاسنتر، بازه را کمی قبل از زمان رخداد شروع کنید تا اتصال‌های قدیمی‌تر را هم بررسی کنید.

زمان فرم و جدول به وقت دستگاه مدیر است، نه الزاماً سرور. در CSV، ستون‌های `started_utc`، `ended_utc` و `last_observed_utc` به UTC هستند؛ زمان‌های JSON میلی‌ثانیه از مبدأ Unix هستند. منطقهٔ زمانی گزارش دیتاسنتر را پیش از مقایسه مشخص کنید.

### معنی ستون‌ها و وضعیت‌ها

| فیلد | معنی |
| --- | --- |
| موتور / حساب | موتور ایجادکننده و ID حساب؛ CottenMax زیر Cotten دیده می‌شود |
| مقصد / IP | نام یا IP درخواستی و IP نهایی بررسی‌شده؛ در شکست زودهنگام ممکن است IP هنوز موجود نباشد |
| پروتکل / پورت | TCP یا UDP و پورت مقصد؛ `purpose` میان DNS داخلی و ترافیک کاربردی تمایز می‌گذارد |
| مسیر | `direct`، `socks5`، `http` یا `https` و endpoint پراکسی بدون رمز |
| آپلود / دانلود | بایت‌های payload رفت و برگشت؛ برای ردیف ناقص، علامت `≥` حداقلِ ثبت‌شده را نشان می‌دهد |
| `active` / فعال | اتصال هنوز باز است؛ نتیجهٔ دانلود یک snapshot از همان لحظه است |
| `completed` / پایان‌یافته | اتصال برقرارشده بسته شده است؛ به‌تنهایی پاسخ موفق HTTP را ثابت نمی‌کند |
| `failed` / ناموفق | برقراری اتصال موفق نشده است؛ علت و تلاش‌ها را بررسی کنید |
| `denied` / ردشده | سیاست دسترسی، محدودیت یا Anti-Flood درخواست را رد کرده است |
| `interrupted` / پایان نامشخص | رکورد پایانی موجود نیست؛ زمان پایان و حجم کامل قطعی نیستند |

CSV علاوه بر جدول، `connection_id`، `attempts`، شمارنده‌های حذف/خطا، آخرین مشاهده و `bytes_known` را دارد. JSON نیز برای تحلیل برنامه‌ای مناسب است. دانلود به صفحهٔ جاری محدود نیست و همهٔ رکوردهای باقی‌ماندهٔ منطبق را می‌دهد؛ سقف هر گزارش **۱۰۰ هزار اتصال** است. برای نتیجهٔ بزرگ، بازه یا موتور/حساب را محدود کنید. فایل شامل اطلاعات مقصد و حساب است؛ پیش از فرستادن برای دیگران، بخش‌های حساس را حذف کنید.

## ۶. ماندگاری، فشار و توقف سرویس

گزارش‌ها به‌صورت خصوصی در `outbound/` کنار دیتابیس، در قطعه‌های چرخشی حداکثر
۱ MiB ذخیره می‌شوند. محدودیت زمان ۱ تا ۷۲۰ ساعت و سقف دیسک ۴ تا ۲۵۶ MiB
است؛ رسیدن به محدودیت حجم می‌تواند تاریخچه را زودتر از مهلت زمانی حذف کند.
نمایش از مهلت زمانی عبور نمی‌کند. حذف فایل‌ها قطعه‌ای است و دادهٔ روی دیسک
ممکن است تا حدود یک ساعت حاشیهٔ گردش داشته باشد.

شروع و پایان اتصال ذخیره می‌شود و جریان‌های فعال هر ده ثانیه checkpoint
دارند. بعد از توقف ناگهانی، ردیف بدون پایان با وضعیت «پایان نامشخص» دیده
می‌شود؛ بایت‌ها حداقلِ آخرین مشاهده‌اند و `bytes_known=false` است. زمان پایان
ساختگی و مصرف صفرِ قطعی نمایش داده نمی‌شود.

مسیر ترافیک منتظر دیسک نمی‌ماند. اگر صف پر یا دیسک خراب شود، شمارندهٔ حذف یا
خطای ذخیره در گزارش آشکار است؛ چنین گزارش‌هایی را کامل فرض نکنید. شمارنده‌های
خطا و حذف از زمان شروع همان پردازش سرویس هستند. CSV هم این
شمارنده‌ها و آخرین زمان مشاهده را دارد. فقط داده‌هایی که واقعاً نگهداری شده‌اند
قابل دانلودند؛ فعال‌کردن ثبت، وقایع گذشته را بازسازی نمی‌کند.

پشتیبان دیتابیس حاوی رمز پراکسی است و باید خصوصی بماند؛ تاریخچهٔ خروجی فایل
جدا دارد. بازیابی حساب‌ها، مسیر خروجی فعلی سرور را حفظ می‌کند تا یک بکاپ قدیمی
خروج مستقیم را ناخواسته برنگرداند. کاهش نسخه به پنلی که Upstream را پشتیبانی
نمی‌کند، این سیاست را اعمال نخواهد کرد.

این کنترل‌ها تشخیص قطعی Botnet/C2 یا تضمین جلوگیری از ساسپند نیستند. برای
بررسی گزارش دیتاسنتر، زمان با منطقهٔ زمانی، IP و پورت مقصد، پروتکل و شواهد
تشخیص لازم است. ترافیک فرایندهای دیگر سرور خارج از این گزارش است.

## ۷. عیب‌یابی و برگشت به تنظیم قبلی

| مشکل یا علت گزارش | بررسی و اقدام |
| --- | --- |
| گزینه‌ها را نمی‌بینم | نسخه باید 0.14.0 یا جدیدتر باشد؛ ارتقا را کامل و صفحه را دوباره بارگذاری کنید. |
| `proxy_unavailable` | اجرای سرویس پراکسی، نوع پروتکل، آدرس و پورت، هر دو فیلد ورود، دسترسی شبکه و در HTTPS اعتبار گواهی/نام را بررسی کنید. این خطا جزئیات خصوصی احراز هویت را نمایش نمی‌دهد. |
| `proxy_udp_unsupported` | درخواست UDP روی HTTP/HTTPS CONNECT رد شده؛ اگر موتور و کلاینت UDP را پشتیبانی می‌کنند، SOCKS5 با UDP ASSOCIATE لازم است. |
| وب‌سایت باز نمی‌شود ولی پراکسی در دسترس است | پورت مقصد، DNS روی TCP از پراکسی، قوانین خروجی همان سرویس، سهمیه و Anti-Flood را بررسی کنید؛ دسترسی به ورودی پراکسی به‌تنهایی کافی نیست. |
| `destination_policy` | پورت مقصد در فهرست مسیر انتخاب‌شده مجاز نیست؛ فهرست مستقیم و پراکسی را با هم اشتباه نگیرید. |
| UDP روی SOCKS5 کار نمی‌کند | خود پراکسی باید UDP ASSOCIATE داشته باشد؛ relay روی میزبان دیگر یا relay با نام دامنه پذیرفته نمی‌شود. |
| IP خروجی تغییر نکرده | موتور درست را تنظیم و از همان موتور دوباره وصل شوید؛ قوانین خروجی Xray/sing-box و احتمال خروج مستقیم آن سرویس را جدا بررسی کنید. |
| گزارش خالی است | ثبت باید پیش از اتصال فعال بوده باشد؛ زمان، منطقهٔ زمانی، فیلتر موتور/حساب و مهلت/سقف نگهداری را بررسی کنید. خاموش‌کردن ثبت، تاریخچهٔ ازقبل ذخیره‌شده را فوراً پاک نمی‌کند. |
| گزارش قدیمی یا صفحه‌بندی غیرفعال است | فیلتر را با «نمایش گزارش» اعمال کنید؛ برای نتایج تازه‌تر زمان پایان را جلو ببرید. |
| خطای گزارش بزرگ یا دریافت طولانی | بازه را کوتاه یا موتور/حساب را مشخص کنید؛ گزارش سقف تعداد و مهلت پردازش دارد. |
| هشدار حذف از صف یا خطای ذخیره | گزارش ممکن است ناقص باشد؛ فضای دیسک، دسترسی نوشتن سرویس و فشار سرور را بررسی و قبل از گردش فایل‌ها خروجی بگیرید. |

برای برگشت، مسیر و پورت‌های سالم قبلی را در همان کارت وارد و ذخیره کنید. انتخاب آگاهانهٔ «مستقیم» یعنی اجازهٔ خروج مستقیم با فهرست پورت اصلی سرور؛ اگر عبور از پراکسی برای شما الزامی است، آن را به‌عنوان راه‌حل موقت انتخاب نکنید و پراکسی سالم قبلی را برگردانید. پنل هنگام خرابی پراکسی این انتخاب را خودکار انجام نمی‌دهد.

برای بررسی Abuse، CSV/JSON بازهٔ مناسب را زود دریافت و با زمان و منطقهٔ زمانی، IP، پورت، پروتکل و شواهد دیتاسنتر تطبیق دهید. وجود یا نبود یک ردیف به‌تنهایی منشأ Botnet/C2 را ثابت نمی‌کند؛ وضعیت ثبت، داده‌های ازدست‌رفته و برنامه‌های دیگر سرور را هم در نظر بگیرید.
